# 代码结构与扩展方式

## 目录与入口

```text
quick-ai/
├─ manifest.json              扩展清单
├─ background.js              后台入口
├─ options.html / options.js  设置页入口
├─ options.css               设置页样式
├─ overlay.js                浮层安装入口
├─ config.js                 默认值、配置规范化和地址处理
├─ chat-completions.js        AI 协议、请求和服务商错误处理
├─ browser-api.js             浏览器 API 入口
├─ src/
│  ├─ background/            菜单、选区读取、请求管理和流式传输
│  ├─ options/               各类编辑器、分区草稿、连接检查和备份
│  ├─ overlay/               浮层视图、会话协调与交互控制器
│  └─ shared/                SSE 分帧和运行时资源清单
├─ scripts/                  静态检查、打包与发布脚本
├─ vendor/                   随包分发的 Markdown 解析器及许可证
└─ dist/                     可重建输出，不提交
```

后台与设置页使用原生 ES 模块。浮层通过 `executeScript` 注入经典脚本，在扩展隔离环境的 `__quickAiOverlayModules` 中注册工厂；最后由 `overlay.js` 安装实例。这样无需构建器、动态导入或新增公开可访问资源。注册工厂与安装浮层均可重复调用，不重复绑定界面事件。

## 职责与依赖方向

### 后台

- `index.js` 绑定浏览器事件并分派消息。
- `context-menus.js` 串行刷新提示词菜单，`selection.js` 只读取活动选区，使用浏览器原生选区文本处理 CSS 段落边界与预格式化空白；不自行遍历整段 DOM 或添加文本缩进。
- `requests.js` 独占标签页请求表、请求 ID 和取消控制器，负责读取最新配置与权限检查。
- `response-stream.js` 通过回调访问当前请求，负责超时与分片合并，不拥有请求表。
- `connection-check.js` 管理设置页的独立连接检查，不复用网页对话控制器。
- `preferences.js` 将本地存储限制为可信上下文，浮层通过白名单消息读写外观与边界。会话存储只保留订阅文档标识，后台休眠不丢失外观同步路由。
- `settings.js` 串行处理设置页的分区保存，对每区块做版本检查，避免多个设置页相互覆盖。
- 请求绑定 `tabId + documentId`；轻量探测协议与安装状态，首次才注入完整脚本。文档离开时取消请求，所有分片按请求 ID 和文档定向交付。

### 设置页

- `app.js` 协调加载、分区保存和控制器。
- `provider-editor.js`、`prompt-editor.js`、`cleanup-editor.js` 各自管理表单与列表；`list-controls.js` 复用搜索、计数与展开操作。
- `drafts.js` 独占保存快照及保存锁，通过收集器读取各区配置，通过保存回调切换选项卡。
- 编辑器通过 `settingschange` 显式通知结构变化；草稿控制器合并 80ms 内的事件，只检查发生修改的区块，保存和离开时同步校验。提示词和清理规则卡片按 ID 复用。
- `backup.js` 管理导入导出；每区块仍按 2 MB 校验，完整备份上限为 8 MB。版本 1 备份的可选 `draft: true` 标记允许恢复未完成项，导入后仍需通过正常保存校验；不导出密钥或 URL 中的凭据、查询参数及片段。`connection-check.js` 管理草稿检查及结果失效；`dialogs.js` 只返回用户选择。

### 浮层

- `app.js` 拥有会话历史、待完成轮次、编辑状态与当前请求 ID，协调其他控制器。
- `view.js` 创建 DOM，`turn-view.js` 创建轮次视图并通过回调通知会话层。
- `stream-renderer.js` 独占当前轮的 Markdown 解析器与分批队列，通过 `reset / append / finish` 接收命令；队列收尾后才调用完成回调。通过 `getBody` 获取当前回复节点，避免新会话沿用旧节点。
- `markdown-renderer.js` 限制链接协议及图片加载；`styles.js` 管理主题和样式。
- `geometry.js` 管理拖动、四角缩放及边界持久化；`appearance.js` 管理字体、主题与外部点击设置；`scroll.js` 管理用户滚动与追问跟随。
- `preferences.js` 是浮层白名单设置客户端，禁止浮层直接访问 `storage`。`request-lifecycle.js` 集中维护连接、等待、生成、收尾和停止阶段，按请求 ID 检查后台状态，并提供独立超时兜底。
- `diagnostics.js` 提供手动开启的本页性能统计，不记录正文或密钥；通过 `refreshVisibility` 与浮层及文档可见性协作，隐藏或离开页面时停止计时器与观察器，恢复时按勾选状态重启，关闭浮层清空统计。渲染每 100ms 调度，单批最多 2048 字符，内部按 256 字符和 6ms 软预算让出主线程；单次解析调用无法强制中断。
- 隐藏时暂停当前回复 DOM 渲染；历史回复折叠后释放正文节点，展开时用同一增量渲染器恢复。会话原文仍由协调器持有，不自动裁剪。

渲染器不修改会话历史；视图不请求服务商；后台不持有浮层对话历史。新增交互优先通过参数与回调连接，不直接读取其他控制器的内部变量。

## 扩展与安全约束

- 新增浮层模块时，将其加入 `src/shared/runtime-files.js` 的注入清单，并按依赖顺序注册。`src/` 会完整打包，其他运行时资源加入同一文件的打包清单。
- 后台与浮层协议发生不兼容变化时，更新 `src/shared/protocol.js` 的版本号。握手失败要求重新加载扩展并刷新网页，不在旧实例上重复安装监听。
- 新增设置项时，同步处理默认值、编辑器、分区收集器、保存逻辑与备份格式；保留已有存储键和历史兼容逻辑。
- 新增服务协议时，在协议层实现，复用后台请求生命周期；API Key 只能由设置页传给后台或由后台读取，不能进入浮层消息。
- 保留流式渲染的 100ms 调度、每批 2048 字符预算、单回复长度上限，以及迟到消息的请求 ID 校验。未完成回复不能提交为对话上下文。
- 隐藏保留内存会话，关闭、新选区和刷新清空；首轮不自动滚动，追问尊重用户暂停跟随的操作。

## 开发命令

无需安装 npm 依赖。Node.js 18+ 可直接运行：

```sh
node scripts/check.mjs
node scripts/package.mjs
```

也可使用 `npm run check` 和 `npm run build`。前者仅检查语法与资源引用，不执行功能测试；后者生成 `dist/chromium/`。重新加载扩展后，刷新目标网页以替换旧浮层脚本。修改模块接口后应按影响范围单独验收浏览器行为，不能用静态检查代替。

`node scripts/check.mjs --package` 另核对安装目录与源码逐字节一致。`scripts/create-release-assets.ps1` 在压缩前执行静态与目录检查，并生成 SHA256 文件。浏览器人工回归步骤见[发布检查](发布检查.md)。
